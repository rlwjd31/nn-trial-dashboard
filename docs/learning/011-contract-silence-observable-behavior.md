# 011. 계약이 침묵하면 구현마다 갈린다 — 스키마 검증기가 못 잡는 것

## 한 줄로
계약에 **적히지 않은** 관측 가능한 동작(정렬·페이지 크기·타이브레이커…)은 구현마다 제각각이 된다.
JSON 스키마 검증기는 **모양**만 보므로 이런 어긋남을 통과시킨다 — 계약에 적어야만 검증 대상이 된다.

## 어떤 상황에서 쓰나

trial 목록 API 에는 mock 구현과 n8n 구현이 둘 다 있고, `pnpm test:contract` 가 응답을
`openapi.yaml` 과 대조한다. **219개 노드 검사, 위반 0건**으로 통과하고 있었다.

그런데 실제 두 구현의 정렬이 반대였다.

| 구현 | 정렬 |
|---|---|
| n8n (실서버) | `ORDER BY l."startAt" DESC` — 늦은 시각이 먼저 |
| mock | `SEED.map(...)` — 9시 → 20시 오름차순 |

검증기는 `trials` 가 배열이고 원소가 스키마에 맞는지만 본다. **순서는 스키마의 표현 대상이 아니다.**
그래서 정반대 순서가 둘 다 "통과"였다. 프론트는 받은 순서를 그대로 렌더하므로,
mock 으로 개발하다 실서버로 붙이면 화면이 뒤집힌다.

이 어긋남은 계약을 읽어서 발견된 게 아니다. **내가 "오름차순이 자연스럽다"고 잘못 제안했다가**
사용자가 "콜 리스트는 늦은 시간이 상단"이라고 정정하면서 드러났다. 계약이 침묵하고 있었으므로
내 제안도 틀렸다고 말할 근거가 문서 어디에도 없었다 — 그게 문제의 본질이다.

## 코드 요약

고친 순서가 중요하다. **계약을 먼저 고치고, 구현들이 거기로 수렴한다.**

`backend/docs/contract/openapi.yaml`:

```yaml
  /trials:
    get:
      description: >
        ...
        **정렬: `trial_time` 내림차순(늦은 시각이 먼저).** 콜 리스트라 늦은 시간이 상단에
        와야 한다는 요구다 — 프론트는 받은 순서를 그대로 렌더하고 재정렬하지 않는다.
        오름차순으로 보이면 백엔드 쪽 회귀다.
```

그 다음 뒤처진 구현(mock)을 맞춘다:

```ts
return {
  trials: SEED.map((s, i) => toListItem(s, dateStr, i))
    .sort((a, b) => b.trial_time.localeCompare(a.trial_time)),
};
```

그리고 **이유를 코드 옆에도** 둔다. n8n UI 에서 쿼리를 여는 사람은 openapi 를 안 볼 수 있다:

```sql
-- DESC 는 의도다: 콜 리스트라 늦은 시각이 상단에 온다. 오름차순으로 되돌리지 말 것(openapi 에 명시).
ORDER BY l."startAt" DESC;
```

## 함정

**1. "테스트가 통과한다"는 "검증됐다"가 아니다.**
검증기가 **무엇을 안 보는지**를 알고 있어야 한다. 이 러너는 모양(타입·필수 필드·enum)만 본다.
순서, 중복, 개수, 헤더 값, 응답 시간은 전부 사각지대다. 통과 개수(219)가 커서 안심했지만
정작 어긋난 축은 세지도 않는 축이었다.

**2. 계약에 안 적힌 건 "자유"가 아니라 "미정"이다.**
"정렬은 명시 안 했으니 아무거나 해도 된다"가 아니다. 프론트는 **어떤 순서든 하나를 가정하고**
코딩한다. 명시되지 않았을 뿐 의존은 이미 생겨 있다. 관측 가능한 모든 동작은 둘 중 하나다 —
계약에 적히거나, 조용한 결합이 되거나.

**3. 근거를 남기지 않으면 다음 사람이 되돌린다.**
"콜 리스트라 늦은 시각이 위" 는 도메인 요구지 기술적 필연이 아니다. 적어두지 않으면
누구든(나처럼) "시간순이 자연스럽다"며 뒤집는다. 그래서 계약 문구에
**"오름차순으로 보이면 회귀다"** 라는 판정 기준까지 넣었다. 값만 적으면 의도는 안 전달된다.

**4. 순서를 계약에 넣었으면 검증도 따라가야 한다.**
지금 러너는 여전히 순서를 안 본다 — 즉 이 계약 조항은 **문서로만 존재**한다.
정렬 단조성 검사를 러너에 추가하는 것이 다음 할 일이다(미구현).
