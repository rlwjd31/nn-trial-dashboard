## 노트 작성 규칙 (에이전트·사람 공통)

새 노트는 아래 골격을 지킨다. 길게 쓰지 말고 **한 노트 = 한 개념**으로 자른다.

```markdown
# NNN. 제목

## 한 줄로
(개념을 한 문장으로. 정의부터.)

## 어떤 상황에서 쓰나
(이 개념이 없으면 무엇이 깨지는지. 우리 코드의 실제 상황으로.)

## 코드 요약
(최소한의 코드. 우리 저장소 파일을 가리킨다.)

## 함정
(몰랐으면 틀렸을 지점. 가능하면 실제로 틀렸던 사례.)

## 이 노트가 나온 작업
(브랜치 · 커밋 · 파일)
```

- **개념 단위로 쪼갠다.** "이번에 한 작업 회고"가 아니라 "다음에 다른 코드에서도 쓸 수 있는 개념"이어야 한다.
- **우리 코드를 근거로 댄다.** 일반론만 있는 노트는 검색으로 대체된다. 파일·커밋을 가리켜서 실물과 연결한다.
- **틀렸던 것을 숨기지 않는다.** 실패한 첫 시도와 그 이유가 이 노트들에서 가장 값나가는 부분이다.
- **검증되지 않은 것은 그렇다고 쓴다.** 추측을 사실처럼 적으면 노트 전체의 신뢰가 깎인다.
- 목록 표에 한 줄을 추가하는 것까지가 한 세트다.
